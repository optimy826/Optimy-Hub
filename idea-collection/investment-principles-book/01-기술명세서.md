# 투자의 정석 — 집필 시스템 명세서

소프트웨어 기술명세서가 아니라, 3년짜리 집필 프로젝트를 "어떻게 꾸준히, 흩어지지 않게 기록할 것인가"에 대한 운영 규칙이다.

## 1. 폴더 구조

```
idea-collection/investment-principles-book/
  00-기획서.md          기획 의도, 독자, 로드맵
  01-기술명세서.md       이 문서 — 집필 규칙
  02-목차초안.md         부/장 단위 목차, 계속 갱신
  templates/
    chapter-template.md 새 장 작성 시 복사용 템플릿
  chapters/
    01-....md           실제 원고 (장 번호 순)
```

## 2. 챕터 파일 규칙

- 파일명: `chapters/<2자리 번호>-<짧은 한글 제목>.md` (예: `chapters/01-왜-투자해야-하는가.md`)
- 번호는 `02-목차초안.md`의 순서를 따른다. 순서가 바뀌면 파일명도 같이 바꾼다.
- 모든 챕터 파일은 아래 프론트매터로 시작한다.

```yaml
---
챕터: 1
제목: 왜 투자해야 하는가
상태: 초안 | 퇴고 | 완성
최종수정: YYYY-MM-DD
핵심키워드: [복리, 인플레이션, 시간가치]
---
```

- 본문은 자유 형식이되, 가능하면 장 끝에 "한 줄 요약"과 "체크리스트"를 둔다 (템플릿 참고).

## 3. 집필 워크플로우

1. 쓸 장을 `02-목차초안.md`에서 고른다.
2. `templates/chapter-template.md`를 복사해 `chapters/`에 번호를 붙여 저장한다.
3. 초안 작성 — 분량이나 완성도보다 "일단 끝까지 쓴다"를 우선한다.
4. 장 단위로 커밋한다 (아래 커밋 규칙 참고).
5. 시간이 지나 다시 읽을 때 퇴고하고, 프론트매터의 `상태`만 갱신한다.
6. 목차가 바뀌면 `02-목차초안.md`을 먼저 수정하고, 그 다음 파일명/챕터 번호를 맞춘다.

## 4. 버전관리(Git) 규칙

- 챕터 하나 = 커밋 하나를 원칙으로 한다. 여러 장을 한 커밋에 묶지 않는다.
- 커밋 메시지 접두사:
  - `plan:` — 기획서/로드맵 수정
  - `outline:` — 목차초안 수정
  - `chapter:` — 챕터 원고 추가/수정 (예: `chapter: 01장 초안 작성`)
- 별도 브랜치 없이 master에 바로 커밋해도 무방하다 (개인 집필 작업이며, Optimy-Hub의 배포 방식상 master push = 즉시 배포이지만, 이 폴더는 허브 HTML에서 직접 링크하지 않으므로 사이트 노출에는 영향 없음).

## 5. 보안·공개 범위 (중요)

이 폴더는 **공개(public) 저장소**인 Optimy-Hub 안에 있다. 즉 이 안의 모든 내용은 깃허브에서 누구나 열람 가능하다.

- 적지 말 것: 실제 자산 금액, 계좌번호, 가족 실명, 특정 회사/상품에 대한 단정적 투자 권유.
- 대신 쓸 것: 일반화된 예시("월급 300만 원을 받는 사회초년생이라면..."), 원칙 중심 서술, 가상의 숫자.
- 만약 민감한 초안을 비공개로 쓰고 싶다면, Optimy-Hub가 아닌 로컬 전용 폴더나 별도 비공개 저장소를 이후에 고려한다 (지금 당장 바꿀 필요는 없음).

## 6. 허브 사이트(optimai-hub.html) 연동 방식

- `optimai-hub.html`의 "아이디어 모음" 섹션 카드가 `idea-collection/investment-principles-book/index.html`로 연결된다.
- `index.html`은 기획서·목차 등 소개 역할만 하는 랜딩 페이지이며, 실제 원고(.md)는 GitHub Pages가 아니라 **GitHub 저장소 자체의 마크다운 렌더링**(`github.com/.../blob/master/...md`)을 통해 보여준다. 이 저장소는 Jekyll 테마가 없는 순수 정적 사이트라 Pages에서 .md를 직접 예쁘게 렌더링하지 못하지만, GitHub 블롭 뷰는 어떤 저장소든 마크다운을 자동으로 렌더링해주기 때문에 별도 변환 없이 바로 활용 가능하다.
- 새 장을 추가하면: (1) `chapters/`에 원고 작성 → (2) `02-목차초안.md`의 체크박스·상태 갱신 → (3) `index.html`의 목차 표에서 해당 장을 `<div class="toc-item">`에서 `<a class="toc-item linked" href="...github blob url...">`로 바꾸고 상태를 "초안 완료"로 변경.
- 추후 정식 발행 형식(전자책/PDF)이 정해지면, 그때 별도의 정식 랜딩 페이지로 교체한다.
